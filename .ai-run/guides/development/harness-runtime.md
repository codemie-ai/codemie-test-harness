# Harness Runtime

**Project**: CodeMie Test Harness · **Stack**: Python pytest 8 + pytest-playwright 0.8 + click CLI (codemie-sdk-python 0.1.709) · **Scope**: settings sources, requirement markers and the capability gate, CLI suite presets and package-root pytest plugins; test authoring conventions live in `.ai-run/guides/testing/strategy.md` and `.ai-run/guides/testing/environments.md`

## Harness runtime

### Rules
- R1. Mark a test that needs an integration with that integration's marker as keyed in `INTEGRATION_SETTINGS` (`jira`, `gitlab`, `servicenow`, ...) or with `requires_setting("KEY")` (a gated run then skips it with `missing setting 'KEY'` when `CredentialsManager.get_parameter` returns an empty value for a listed key, and fails it under `--strict-requirements` or `HARNESS_STRICT=1`; a test that also carries `<name>_cloud` is gated by the Cloud keys only). Evidence: `codemie_test_harness/capability_gate.py::CapabilityGate._unmet`
- R2. Mark a test that needs a platform feature with `requires_capability("<name>")`, where the name is a key of `CAPABILITIES` or a `GET /v1/config` component id (the gate treats the capability as present when any mapped component is enabled; a `datasource` marker already implies `retrieval` through `MARKER_CAPABILITIES`). Evidence: `codemie_test_harness/capability_gate.py::MARKER_CAPABILITIES`
- R3. Add the setting keys of a new integration to `INTEGRATION_SETTINGS` under its marker name when that marker should gate its tests (`CapabilityGate._unmet` gates only markers listed there; any other marker gates nothing). Evidence: `codemie_test_harness/capability_gate.py::INTEGRATION_SETTINGS`
- R4. Expect no gating in a narrowed run: a node id, `-k`, a file, a directory below a test root or `--no-gate` turns the gate off, so a test whose setting or capability is missing runs and fails instead of skipping (check its settings before debugging the product). Evidence: `codemie_test_harness/capability_gate.py::is_gated_run`
- R5. Put the settings of a direct `pytest` run in the environment or in `codemie_test_harness/.env` (values saved with `codemie-test-harness config set` reach a run only through the CLI: `ensure_env_from_config` is called from `cli/cli.py`, `cli/commands/run_cmd.py` and `cli/interactive.py`, and `CredentialsManager._lookup` reads `os.getenv`). Evidence: `codemie_test_harness/cli/utils.py::ensure_env_from_config`
- R6. Expect the local-stack defaults of `codemie_test_harness/.env.template` only when `codemie_test_harness/.env` is missing, `CODEMIE_API_DOMAIN` is unset or local, and neither `HARNESS_SECRET_STORE` nor an AWS credential variable is set (otherwise nothing is loaded and an unset setting stays empty; existing environment variables are never overridden). Evidence: `codemie_test_harness/tests/utils/env_utils.py::_load_env_file`
- R7. When you rename a setting, map the old name to the new one in `KEY_ALIASES` (`CredentialsManager._lookup` reads the old name from the environment and `load_config` renames it in the config file, so existing setups keep working). Evidence: `codemie_test_harness/cli/constants.py::KEY_ALIASES`
- R8. Declare a new setting key as a `KEY_*` constant in its category list in `cli/constants.py`, and add it to `SENSITIVE_KEYS` when it holds a secret (`config integrations` shows only keys in `INTEGRATION_KEYS`, and `config list` and `config set` mask only `SENSITIVE_KEYS`). Evidence: `codemie_test_harness/cli/constants.py::SENSITIVE_KEYS`
- R9. Add a CLI suite preset as an entry of `TEST_SUITES` with `marks`, `workers`, `reruns`, `description` and, for a UI suite, `"pytest_args": ["--ui-headless"]` (`_add_suite_flags` builds the `--<name>` shortcut from the dict, and `browser_type_launch_args` runs the browser headed unless `--ui-headless` is passed). Evidence: `codemie_test_harness/cli/cli.py::_add_suite_flags`
- R10. Keep `otlp_builder.py`, `ingest_sender.py`, `rp_guard.py`, `results_plugin.py` and `capability_gate.py` free of module-level imports from `codemie_test_harness.tests` (that package's `__init__` calls `load_env_file` on import; `capability_gate.py` imports `CredentialsManager` inside `CapabilityGate._unmet`). Evidence: `codemie_test_harness/tests/__init__.py::load_env_file`
- R11. Log from UI fixtures and hooks through `get_rp_logger(config)` and attach files with `log_with_attachment` (both fall back to a plain logger when pytest-reportportal is not reporting the run, so the code works without Report Portal). Evidence: `codemie_test_harness/rp_guard.py::get_rp_logger`
- R12. The repository is public: no ticket key, internal host, personal e-mail or customer name. Placeholder form only in `.ai-run/guides/project.md`. Allowed exceptions: `codemie_test_harness/tests/utils/env_resolver.py`. Evidence: `codemie_test_harness/tests/utils/env_resolver.py::EnvironmentResolver.HOST_PATTERNS`

### Constraints
| Do not | Do instead | Why | Evidence |
|---|---|---|---|
| Read the project name with `os.getenv("PROJECT_NAME")` | Import `PROJECT` from `codemie_test_harness.tests` | `PROJECT` defaults to `codemie`, which `ensure_test_project` creates; `os.getenv` returns `None` when the variable is unset | `codemie_test_harness/tests/__init__.py::PROJECT` |
| Create or look up an external-system seed inside each test or worker | An idempotent `ensure_seed_*` helper resolved once per run through `resolve_shared` in a session fixture | `resolve_shared` runs the helper once under a file lock shared by the xdist workers and caches its JSON result | `codemie_test_harness/tests/utils/jira_seed.py::resolve_shared` |
| Instantiate `RPLogger` or call `logging.setLoggerClass` | `get_rp_logger(config)` | builds the Report Portal logger only when the plugin reports, without changing global logging state | `codemie_test_harness/rp_guard.py::get_rp_logger` |

### Read first
| When you are | Exemplar | Why this one | Tests |
|---|---|---|---|
| adding a test that needs an integration | `codemie_test_harness/tests/assistant/tools/vcs/test_gitlab_tool_image_responses.py::test_gitlab_tool_downloads_uploaded_image_for_assistant` | `requires_setting` plus the integration marker, `api` last above `def` | exemplar is a test |
| adding a shared seed fixture for an external system | `codemie_test_harness/tests/conftest.py::_jira_seed` | `resolve_shared` with `_seed_lock_dir`, payload round-tripped through `to_dict` / `from_dict` | `codemie_test_harness/tests/assistant/datasource/test_jira_datasource.py::test_create_jira_datasource_with_custom_fields` |
| adding a pytest plugin at the package root | `codemie_test_harness/results_plugin.py::pytest_configure` | option read in `pytest_configure`, registered on the controller only (`workerinput` check), no import from `codemie_test_harness.tests` | no covering test |
| adding a CLI suite preset | `codemie_test_harness/cli/constants.py::TEST_SUITES` | one dict entry per suite; UI presets carry `--ui-headless` | no covering test |
