# Settings Guide

**Project**: codemie-test-harness · **Stack**: Python, pytest 8 + codemie-sdk-python 0.1.709 + pytest-playwright 0.8 (CLI: click 8) · **Scope**: reading harness settings and credentials, gating tests on them, and SDK client construction; CLI and pytest config loading live in `.ai-run/guides/architecture/architecture.md`

## Configuration

### Rules
- R1. Read a harness setting with `CredentialsManager.get_parameter("KEY")`, not `os.getenv`; only `_lookup` resolves the earlier key names in `KEY_ALIASES`, the opt-in AWS Parameter Store mapping and the `CREDENTIAL_MAPPINGS` default. Allowed exceptions: `codemie_test_harness/tests/utils/env_resolver.py`, `codemie_test_harness/tests/utils/env_utils.py`, `codemie_test_harness/tests/utils/aws_parameters_store.py`, `codemie_test_harness/tests/utils/credentials_manager.py`, `codemie_test_harness/tests/__init__.py`. Known debt, to fix: `codemie_test_harness/tests/assistant/datasource/test_azure_devops_wiki_datasource.py`, `codemie_test_harness/tests/assistant/datasource/test_azure_devops_work_items_datasource.py`, `codemie_test_harness/tests/assistant/datasource/test_code_datasource.py`, `codemie_test_harness/tests/assistant/datasource/test_confluence_datasource.py`, `codemie_test_harness/tests/assistant/datasource/test_google_datasource.py`, `codemie_test_harness/tests/assistant/datasource/test_jira_datasource.py`, `codemie_test_harness/tests/e2e/test_e2e.py`, `codemie_test_harness/tests/ui/chats/test_image_allow_list.py`, `codemie_test_harness/tests/ui/workflows/test_create_workflow.py`, `codemie_test_harness/tests/user/test_user_info.py`, `codemie_test_harness/tests/test_data/direct_tools/open_api_tools_test_data.py`, `codemie_test_harness/tests/ui/administration/conftest.py`, `codemie_test_harness/tests/ui/conftest.py`. Evidence: `codemie_test_harness/tests/utils/credentials_manager.py::CredentialsManager.get_parameter`
- R2. Declare what a test needs instead of reading an empty value: an integration marker that is a key of `INTEGRATION_SETTINGS` (`jira`, `gitlab`, `servicenow`, ...) or `@pytest.mark.requires_setting("KEY")` for settings, `@pytest.mark.requires_capability("name")` for a `/v1/config` component; in a gated run `CapabilityGate.pytest_runtest_setup` skips the test as `missing setting 'KEY'` or `missing capability 'name'` (a failure with `--strict`), while `get_parameter` alone returns `""` into the test. Evidence: `codemie_test_harness/capability_gate.py::CapabilityGate._unmet`
- R3. Check the skip of a new `requires_*` test with a suite run, not with `-k`, a node id, a file or sub-directory path, or `codemie-test-harness run --marks`; `is_gated_run` returns False for the first four and `run_cmd` adds `--no-gate` to `--marks`, so there the test runs and fails on the missing value. Evidence: `codemie_test_harness/capability_gate.py::is_gated_run`
- R4. Build SDK clients only through `get_client` and pass the `VERIFY_SSL` constant of `codemie_test_harness.tests` to a raw `RequestHandler`. The intended default is TLS verification on: an unset `VERIFY_SSL` means verify, as `tests.VERIFY_SSL` reads it. Known debt: `get_client` still reads an unset value as false and README.md documents that, so set `VERIFY_SSL` explicitly until it is fixed. Known debt, to fix: `codemie_test_harness/tests/utils/client_factory.py`, `README.md`. Evidence: `codemie_test_harness/tests/utils/client_factory.py::get_client`
- R5. Put a new local-stack default in `codemie_test_harness/.env.template`, not in `.env` (git-ignored); `_load_env_file` loads the template only when `.env` is missing, `CODEMIE_API_DOMAIN` is unset or a local host, and neither `HARNESS_SECRET_STORE` nor an AWS credential variable is set, and it never overrides a variable already in the environment. Evidence: `codemie_test_harness/tests/utils/env_utils.py::_load_env_file`
